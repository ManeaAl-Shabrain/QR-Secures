# Security Policy

## Reporting a problem

Please do not place passwords, private links, access tokens, personal data, or instructions for exploiting the application in a public issue. Contact the repository owner privately through the GitHub profile. Explain which part is affected, what could happen, how to reproduce the problem safely, and how it might be fixed.

## Current security work

Four backend analysis or alert functions still need caller verification. Testing should also confirm the data access rules, role permissions, protection against redirects to private networks, secure storage of secrets, limited Slack content, request limits, and useful audit records.

## Safe testing

Use domains and QR codes created for testing. Do not scan passwords, private invitations, password reset links, internal systems, or customer information. Test only systems that you own or have permission to examine.
